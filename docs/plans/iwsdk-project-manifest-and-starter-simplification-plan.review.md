# Final Review: IWSDK Project Manifest and Starter Simplification Plan

**Plan reviewed:** `docs/plans/iwsdk-project-manifest-and-starter-simplification-plan.md`
**Repo state:** `stack/iwsdk-editor-player-spaces` @ `9ef13268` (checkout: `webxr-dev-platform-iwsdk-restack-audit`)
**Review date:** 2026-07-30
**Method:** 9 parallel dimension audits, each adversarially re-verified against the source by a second reader, plus a completeness critic and a steelman pass (21 agents, 137 surviving findings, 4 critical / 64 major). All `file:line` citations below were opened by a reviewer; a sample of the top ten was independently re-checked before publication.

## Verdict

The plan is sound and I would not send it back. Its current-state diagnosis survives file-by-file verification — the two-pass pipeline, six variants, CAS store, and chef-verify are described exactly as they exist (`packages/starter-assets/scripts/generate-starters.mjs:26-39,406-411`; `build-assets.mjs:24,86-102,651-674`) — and the Non-Goals section (L76-89) forecloses the framework creep that kills most manifest migrations by refusing `defineApp()`, refusing serialized systems, and refusing to keep the Chef recipe format as a compatibility layer. The single biggest problem is that the plan deletes the `ai`/`workspace`/`iwer` branches from `vite.config.ts` without defining any replacement: the proposed manifest has no field that turns on the managed workspace, and bare `iwsdkDev()` produces no editor at all (`packages/vite-plugin-dev/src/index.ts:239,588-590`) — while three phase gates and acceptance criterion 4 all require the editor to mount. Disposition: **approve with amendments, and promote the CDN publication track to an independently landable workstream** — which the plan already authorizes at L1187-1189 and gives an interim contract for at L673-674, but leaves as footnotes rather than structure. Roughly 100 raw audit findings deduplicate to ~30 distinct issues; most amendments are one to three lines, and only two change the plan's shape.

## Blocking issues

**1. The manifest has no field to enable the managed workspace, and the `iwer` inference is wrong.** L574 proposes `plugins: [iwsdkDev()]`; L607 removes "the `ai` versus `workspace` split"; the `dev` block (L301-306) contains only `emulator.device`. In reality `processOptions` sets `processed.workspace` only when `options.ai` or `options.workspace.enabled` is present (`packages/vite-plugin-dev/src/index.ts:239`), and `configureServer` returns at `:588-590` before the MCP server, runtime-session registration and managed browser. Separately, L345-348's "IWER is inferred as unnecessary" for Desktop discards the whole `ai` block (`index.ts:209-219`) and stops `shouldActivate()` (`injection-template.ts:37-46`), so the app tab never gets `initMCPClient` (`injection-template.ts:220-237`) — leaving only the degraded editor bridge (`mcp/ws-client.ts:471-491`). `examples/browser-first/vite.config.ts:14-23` is the live counterexample: an `xr:false` world that deliberately keeps IWER and `ai: { mode: 'collaborate' }`. This breaks gates L793, L1002-1003, L1016 and criteria L1122/L1135. **Amendment:** add `dev.workspace { enabled, open, headless, screenshotSize }` and `dev.ai { mode, screenshotSize }` to the contract with per-target values and stated defaults; preserve the sibling plan's contract that `ai` implies workspace but workspace is independently enablable (`docs/plans/iwsdk-managed-workspace-scene-editor-plan.md:470-471`); do not derive `iwer` from `world.xr`.

**2. Phase 6's gate is a three-token grep against ~15 hard consumers, several of which break earlier than Phase 6.** The gate (L1031-1032) searches for "recipe, template-directive, or `iwsdkExampleAssets`". None of these match: `packages/create/package.json:54` (`"@iwsdk/starter-assets": "workspace:*"`) plus `pnpm-lock.yaml:244-246`, which breaks `pnpm install --frozen-lockfile` — the first step of both CI jobs (`.github/workflows/native-scene-editor.yml:60-61,117-118`); `packages/create/package.json:20`, whose `test` script builds the package and is invoked by the Sandcastle lane (`ci/sandcastle/run-check.sh:67-72`); root `package.json:37,38`; `scripts/check-canonical-mcp-surface.mjs:20-27` with an unguarded `stat` (`:128-130`) that exits 1; `scripts/native-scene-release-rehearsal.mjs:44-51`; `scripts/build-bundle.sh:79-95` (hard `exit 1` on missing recipes); `.github/workflows/native-scene-editor.yml:15,32`; three pending changesets (`.changeset/direct-uikitml-runtime.md:3`, `fresh-pandas-create.md:3`, `native-scene-editor-replaces-metaspatial.md:7`) that abort `changeset version` under the `fixed: [["@iwsdk/*"]]` group (`.changeset/config.json:5`); `packages/cli/test/cli.test.ts:915-937`, which reads the template through a hard-coded absolute path into a different checkout; and `packages/reference/src/query-handlers.ts:233,244`, which demotes `packages/starter-assets/` to priority 4 — so a relocated `packages/create/template/**` silently jumps to priority 1 and outranks real SDK sources in agent search. **Amendment:** replace the gate with an executable checklist naming each file, plus "`pnpm install --frozen-lockfile`, `pnpm test:canonical-mcp-surface`, `test:native-scene-examples`, `test:create-flow-e2e`, `changeset status`, and `bash scripts/build-bundle.sh` all pass with the directory deleted"; add a policy line that published 0.4.x versions stay on npm (`packages/create/src/recipes.ts:12-14` still resolves them) plus an `npm deprecate`.

**3. The harnesses that must prove Phases 2, 4 and 5 are coupled to exactly what those phases delete.** `packages/create/tests/create-flow-e2e.test.ts:115` stats `packages/starter-assets/dist/recipes/index.json` in `beforeAll`, so Phase 4's gate ("scaffold without `@iwsdk/starter-assets`") is literally unrunnable; `:425-446` hard-asserts today's per-target scene filename, the `ai`/`workspace` split, and browser-absent files. `scripts/check-native-scene-examples.mjs:329-338` fails a config for _lacking_ `iwsdkExampleAssets`, `:604-609` requires the literal `assetManifest: './src/assets.ts'`, `:592-602` greps `index.ts` text, and `:296,432-436` requires `packages/starter-assets/dist/assets` — so the first migrated example turns CI red with an inverted error, and the Phase 6 gate can never pass while `:329` demands the string. `packages/vite-plugin-dev/test/editor-e2e-fixture.ts:111-115` passes `assetManifest`/`componentManifest` for ~28 editor e2e specs. **Amendment:** move each rewrite into the phase that breaks it — fixture into Phase 2 (gate: "editor e2e green against a manifest-only fixture"), create-flow-e2e into Phase 4 (gate: "passes with `packages/starter-assets/dist` absent"), `check-native-scene-examples.mjs` to the _start_ of Phase 5. Resolve L839-840 in favour of a deprecation warning for 0.5 so the fixture migration and the manifest path validate independently.

**4. Version pinning and Create packaging both have no owner.** `build-assets.mjs:433-450` rewrites the template `package.json` name to `{{ @appName }}` and every `@iwsdk/*` dep to a Chef variable set to `VERSION` (`:442`, from `scripts/version.js:1`) — the committed source ships `file:../packages/core/iwsdk-core.tgz` (`starter-template/package.json:17,21-24`), so Generation Algorithm step 7's "write the common source unchanged" (L738) produces an `npm install` failure for every npm-mode scaffold. Make the package-content test run against `npm pack` output. Also make Create compare its VERSION against `bundle.json.sdkVersion` (`source.ts:35`, currently declared and never read), since `scripts/build-bundle.sh:58-61` deliberately excludes Create from the canary bundle — post-move, template/SDK skew becomes undetectable.

**6. `welcome.uikitml` is target-templated, and `PanelSystem` is structurally XR-only.** It is one of five files carrying `@template:` directives — two if/else blocks at `:28-44` and `:47-59`, including `<button id="xr-button">Enter XR</button>` at `:58` — and `generate-starters.mjs:353-354` deletes it wholesale for browser. "Reuse the VR scene seed for Desktop" is a Desktop content bring-up, and Desktop has no way to look around.** `browser.iwsdk.scene.json:19` is `"nodes": []`; the browser recipe ships `assets = {}`, `defineComponents([])`, and an empty `.then()`; `generate-starters.mjs:349-357` deletes panel/robot/uikitml/audio/textures. ## Significant gaps

**`packages/scene-composition` is absent from the work breakdown.** It owns `validateSceneDocument()` and the scene JSON Schema (`packages/scene-composition/package.json:4`, `src/validation.ts:62`), is a hard dependency of core, vite-plugin-dev and Create, and `SceneDocumentValidationOptions` (`src/validation.ts:50-60`) has no asset-catalog slot — so L364's headline rule ("every scene asset reference is present in the selected asset set") cannot be implemented in the packages the plan lists. `check-native-scene-examples.mjs:499-549` already implements the rule; lift it rather than reinvent it. This is new public API on a fixed-version-group package.

**Guidance relocation is a content rewrite, not a move.** The shipped skills teach the retired surface: `claude-injections/skills/iwsdk-scene-composer/references/asset-authoring.md:19` instructs `iwsdkDev({ assetManifest })`, `scene-format.md:62,298` the same, `iwsdk-planner/references/api-reference.md:1242` documents `public/iwsdk-assets/`. A verbatim relocation ships agent instructions that tell coding agents to write a hard error. A second, already-drifted copy lives at repo-root `.claude/skills/iwsdk-planner/references/api-reference.md:1227` with no sync check. And `pnpm audit:metaspatial` is already red — 13 non-allowlisted references, two of which are this plan document (`:16`, `:19`), the rest in the very migration skill the plan relocates.

**`packages/cli` is missing entirely.** It owns MCP adapter registration, which Create shells into after install (`packages/create/src/cli.ts:610-632` → `packages/cli/src/runtime-contract.ts:189-192`), project-root detection keyed off `vite.config.*` rather than the manifest (`runtime-state.ts:180-208`), and the hard `dev:runtime` script requirement (`commands/dev.ts:236`). The generated `package.json` also carries `@meta-quest/hzdb` telemetry (`starter-template/package.json:25`). None of these appear in the Create Matrix, which asserts only absences.

**Evidence regeneration has no owner.** 81 tracked files under `docs/test-evidence/` with SHA-256 manifests; `check-native-scene-starter-evidence.mjs:241-245` asserts a node id `scaffold-added-plant` that Phase 3's scene rewrite invalidates; `:23` excludes `generated-browser` from `TARGETS` even though `create-flow-e2e.test.ts:847-850` captures and commits it — so the Desktop hypothesis cannot currently be machine-falsified. There is also no non-`current/` slot for a Phase 0 baseline.

**`virtual:iwsdk-project` has no type-declaration delivery path.** The starter tsconfig sets `"types": []` (`starter-template/tsconfig.json:12-14`), no example has any `.d.ts`, and `@iwsdk/vite-plugin-dev` exports no `./client` entry (`package.json:8-25`) — so the obvious "ship it in the package" answer silently does not work, and `pnpm typecheck:examples` (`package.json:21`) fails on the first migrated example. The starter also has no `typecheck` script at all, so gate L1085 is unenforceable.

**The editor never derives its scene from project config.** `resolveEditorScenePath` reads only `?scene=` (`index.ts:6031-6040`) with a fallback to `public/scenes/scene.iwsdk.scene.json` (`:6046-6049`) that nothing ships; `createEditorShellHtml` is called with no scene (`:1883-1901`). Acceptance criterion 4 and the "config-selected scene loads" test (L1094) have no work item.

**`assets.include` is an authoring gate, not a preload filter, and has no default.** `RenderableAssetRegistry` feeds preload and the editor catalog from one object (`asset-manager.ts:135-152,211-221`), and `scene-editor-session.ts:1663-1680` hard-rejects unplaced ids — so filtering removes assets from the drawer. No default is stated, which would force every single-target example to re-enumerate its whole manifest (grab: 13 ids), and 7 of 10 examples have no components module at all, so `components` must be optional.

## Corrections to the plan's description of current state

- **`scene` vs `level`.** `WorldOptions` has `level`, not `scene` (`world-initializer.ts:126`). The plan orders an old-to-new configuration table (L873) but never states the mapping itself.
- **Two of six sample `assets.include` ids do not exist and cannot work.** The real keys are `chimeSound` and `webxr` (`assets.template.ts:44,54`). `webxr` is `AssetType.Texture`, which `instantiate()` rejects (`asset-manager.ts:170-186,250-257`), so it can never be scene-placed; the seeds reference audio by raw URL (`vr.iwsdk.scene.json:64-68`) not by key, which also causes a duplicate fetch today.
- **"Two independent source-transformation implementations" undercounts.** There are four directive families. `@iwer-sem-*` and the Pass-2 `@template:` lexer are already dead; the live second pass (`build-assets.mjs:230-259`) is what carries prompt-driven feature selection from `cli.ts:503-511` into `src/index.ts` — deleting it as "redundant target templating" would silently drop locomotion/grabbing/physics configuration.
- **Five guidance recipes, not four** (`build-assets.mjs:542-552` emits `base-agents-config`), and Cursor/Copilot/Codex outputs are _derived_ from `PROJECT_AGENTS.md` (`:558-577,582-596,602-630`), not stored as separate sources. The relocation inventory (L771-777) names `.claude/skills/**`; the real source is `claude-injections/{skills,agents,settings.json}`.
- **The common source tree omits `.gitignore`, `.nvmrc` and `README.md`**, all of which ship in every generated project today, and the `.gitignore` ignores `.mcp.json`/`.codex/config.toml` — the files the CLI auto-generates. `src/mouselook.ts` is deleted in _both_ branches (`generate-starters.mjs:351,358`) and ships nowhere; say so.
- **`$schema` points outside the published tarball.** `packages/core/package.json:26-28` is `"files": ["dist"]`, so `./node_modules/@iwsdk/core/iwsdk-project.schema.json` dangles after install.
- **Risk row 8's mitigation misdirects.** `replayExisting` already exists (`elics/lib/query.d.ts:31`) and `registerQuery` already back-fills entity sets (`query-manager.js:32-38`). The real defect is that `subscribe('qualify', cb)` does not replay by default — a call-site fix, not a query-semantics change.
- **Risk row 10's rationale is wrong** ("guidance is text"): a 340 KB PNG and an MP3 move too. The conclusion still holds.
- **Phase 0 capture will fail as written.** `build-assets.mjs:727` rimrafs the six intermediate trees at the end of every successful build; use `starter:sync` or capture from `dist/recipes`.

## Judgement calls worth revisiting

**The four decisions are mis-prioritized.** CDN provider (decision 3) is the most reversible of the four — the plan itself says a Meta mirror needs no ID change if the base URL is centralized (L127-128). Meanwhile four irreversible decisions are absent: (a) is `virtual:iwsdk-project` public semver-protected API, and is that its final name? It is still "provisionally named" at L443 yet ships in every generated `index.ts` from Phase 4 and in the migration guide (L917). (b) Hard error versus deprecation for legacy plugin options (L839-840) — this decides whether the 28-spec editor suite dies on day one of Phase 2. (c) Is `iwsdk.config.json` hand-editable and committed, or tool-owned? This determines the `assets.include` answer. (d) Do XR/feature normalizers ship from `@iwsdk/core` (L823-824), given the promise at L455-456 that non-Vite consumers can construct the same object? _Counter-argument:_ the plan hedges field names at L309-310 and reserves `dev` at L319, so these are arguably Phase 2 detail. That defence fails for (a) and (b), which cannot be deferred past the phases that consume them.

**Desktop shares the VR seed.** _Counter-argument, and it is a good one:_ the plan frames this as a falsifiable hypothesis with a pre-authorized split in three places (L129-131, L981, risk row L1164). That is the right procedure. But the approver at Phase 0 has no delta to weigh, and the evidence that will falsify it is already visible in the repo — so the hypothesis should be resolved at Phase 0, not late in Phase 7.

**Independent versioning of `@iwsdk/example-assets`.** _Counter:_ `.changeset/config.json:5` and `RELEASE.md:3` must both change, and decoupling creates a second release train. _For:_ without it, `updateInternalDependencies: patch` republishes the package on every routine SDK release, so every pinned CDN URL in every example and starter needs rewriting each time — which destroys the immutability premise the whole design rests on. Decouple, and name the config edit as a Phase 1 artifact with the gate "a changeset bumping `@iwsdk/core` does not bump `@iwsdk/example-assets`".

**CDN versus publishing the package and keeping the copy plugin.** _For CDN:_ it collapses four divergent delivery paths into one and incidentally fixes subpath deployment, since every consumer pairs `base: './'` with root-relative asset URLs (`examples/grab/vite.config.ts:40` vs `src/assets.ts:14`). That argument is stronger than "keep generated projects small" and the plan under-argues it. _Against:_ docs-site demos become jsDelivr-dependent (`scripts/build-examples.sh:33,52-57`), and it removes the `assetRoot` contributor loop (`packages/example-assets/src/vite.ts:50-54`) with no replacement for SDK contributors iterating on stock models. Add an env-overridable base URL and decide the docs-build question explicitly.

**Phase 1 first.** _Counter:_ the plan already prescribes splitting the publish (L1187-1189) and already defines the interim test contract (L673-674) — two reviewers demanded a remedy the plan contains. But the license/provenance audit is the one task that can fail for reasons no engineer can fix (`packages/example-assets/src/catalog.ts:22-32` has no license/source/attribution field, no LICENSE ships, `git log --follow` yields no source URL), and it currently blocks a purely internal refactor.

## What the plan gets right

The Non-Goals section is the best part of the document and the one thing hardest to reverse after 0.5.0. Pinning "systems are intentionally absent" (L320) while keeping complete `world.registerSystem(System, { priority, configData })` calls in TypeScript keeps the manifest a data file rather than a DSL, and L89's refusal to preserve the Chef recipe format as a compatibility layer is what makes Phase 6 clean at all.

`defineAssets()` is derived from real code, not invented: `defineComponents` (`packages/core/src/ecs/component-manifest.ts:29-50`) already does blank-ID checks, duplicate checks, a non-enumerable brand and `Object.freeze`, with an existing test to copy (`tests/ecs/component-manifest.test.ts:50-58`), and the parented-prototype rejection already exists (`asset-manager.ts:143-149`) — the helper moves an existing check earlier.

The preload characterization is exact (`asset-manager.ts:305-333`, `world-initializer.ts:291-300,879-906`), filtering before `World.create` is mechanically safe because built-in primitives are merged separately (`asset-manager.ts:105-122,142`), and the plan correctly refuses to redesign lazy loading inside this migration (L420-422).

The central architectural constraint already holds: the plugin never evaluates app modules in Node (`index.ts:1638-1690`; the real `import()` happens in the browser realm at `editor-runtime-source.ts:481-503`), so Phase 2 needs no rework budget for the realm model. The manifest is genuine greenfield — `iwsdk.config` has zero hits repo-wide outside this document.

The plan names the single riskiest migration hazard at its exact line (`panel.ts:17` `requireSceneObject`), and deleting scaffold-time recipe fetching fixes a shipping product defect: `recipes.ts:12-14` fetches from jsDelivr with an `@latest` fallback at `:36-41` that can silently scaffold a different version's starter when indexing lags. Finally, the URL contract holds under measurement: the packed tarball path matches (`package/assets/robot/robot.gltf`), every glTF `images[].uri` is a bare same-directory filename with base64 buffers so relative resolution never escapes the versioned directory, and jsDelivr returns `access-control-allow-origin: *` with `model/gltf+json`.

## Recommended amendments to the phase plan

**Split into two tracks with separate Definitions of Done**, promoting L1187-1189 and L673-674 from footnotes to structure. **Track B (Immutable Asset Distribution)** = current Phase 1, the CDN parts of Phase 5, and the publication test suite, landable independently. **Track A (Manifest + Starter + Create)** = Phases 0/2/3/4/6 plus the non-CDN parts of 5/7, running against today's `/iwsdk-assets/` delivery behind a centralized base-URL constant whose `assetIds` are derived from `assets.include`, so the eventual CDN switch is a base-URL change plus one plugin deletion.

- **Phase 0 (expanded).** Add: inventory all ten examples' real `World.create` shapes plus both starter trees; capture golden per-target file lists via `starter:sync`; write the Desktop delta into Decision 4; add decisions 5-8 above; allowlist this plan doc in `check-metaspatial-removal.mjs:78-89`; repair the stale `grab` entries in both proof scripts before baselining; store the baseline outside `current/`.
- **Phase 2 (+ fixture, + schema freeze gate).** Add `dev.workspace`/`dev.ai`/`dev.emulator.*` fields; the `scene-composition` asset-catalog validation option; `virtual:iwsdk-project` declaration delivery plus a `typecheck` script; `addWatchFile` plus `server.restart()` for emulator changes (a page reload cannot work — values are compiled into the injection bundle at `buildStart`, `injection-bundler.ts:34-56`); migrate `editor-e2e-fixture.ts`. **Gate:** editor e2e suite green against a manifest-only fixture, _and_ the hand-authored app.
