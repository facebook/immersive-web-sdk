# Native Scene Manual Smoke Evidence

Phase 11 of the native scene editor replacement requires physical Quest/browser
smoke for:

- VR starter
- AR starter
- grab example
- physics example
- audio example

Generate the evidence template:

```bash
node scripts/check-native-scene-manual-smoke.mjs \
  --write-template docs/test-evidence/native-scene-manual-smoke.json
```

Fill every target with:

- `status: "passed"`
- the URL opened in Quest Browser
- the command used to serve or scaffold the target
- all required checks set to `true`
- at least one local screenshot or video artifact `path`; external URLs are
  optional sharing metadata and are not enough by themselves
- optional log artifacts when they help explain the run

Validate the evidence:

```bash
pnpm test:native-scene-manual-smoke -- \
  --evidence docs/test-evidence/native-scene-manual-smoke.json
```

Require it during release rehearsal:

```bash
node scripts/native-scene-release-rehearsal.mjs \
  --require-manual-smoke \
  --manual-smoke-evidence docs/test-evidence/native-scene-manual-smoke.json
```

The normal release rehearsal omits this step so CI and local machines without a
Quest can still run the automated gate. Release signoff should use
`--require-manual-smoke`.

Automated app/editor render proof is generated separately and is part of the
default release rehearsal:

```bash
pnpm test:native-scene-render-proof
```

That command writes the current evidence bundle under
`docs/test-evidence/native-scene-examples/current/`.

Generated VR/AR starter app/editor proof is generated by the create-flow install
E2E during the default release rehearsal and by:

```bash
pnpm test:create-flow-e2e
```

It writes:

```text
docs/test-evidence/native-scene-starters/current/generated-vr/
docs/test-evidence/native-scene-starters/current/generated-ar/
```

Each generated-starter directory includes app/editor screenshots, an
app-after-reload screenshot, and `proof.json` with WebGL editor proof, scene
before/after data, asset network observations, runtime hierarchy, and ECS
component counts after reload.

Validate the generated-starter evidence:

```bash
pnpm test:native-scene-starter-evidence
```

Native editor E2E evidence is validated by the release rehearsal as a separate
machine-checkable bundle:

```bash
pnpm test:native-scene-editor-evidence
```

That command validates `docs/test-evidence/native-scene-editor/current/` for the
required WebGL proof, network/console health, named-view screenshots, image
diffs, performance thresholds, saved scene mutations, and app reload parity. On
success it writes `evidence-manifest.json` with command, browser, package, and
file hash metadata.
The release rehearsal regenerates that directory during the native
editor/browser test step before running this verifier.

Release package and documentation artifacts are recorded by:

```bash
pnpm test:native-scene-release-artifacts
```

After scanning the actual tarballs and built documentation, that command writes
`project-manifest-release/current/artifact-manifest.json`. The manifest records
every packaged file path, tarball hashes, the built-docs tree hash, hashes or
missing status for the other evidence bundles, the exact browser-console
allowlist, and any gate that still prevents combined release signoff. A missing
physical-headset evidence file is reported as a blocked gate rather than being
silently treated as an automated pass.

The independently published stock-asset package is verified with:

```bash
pnpm --filter @iwsdk/example-assets verify:cdn -- \
  --version 0.4.2 \
  --report /absolute/path/to/docs/test-evidence/project-manifest-release/current/example-assets-cdn-report.json
```

The report records the exact jsDelivr URL, CORS/MIME responses, byte sizes and
SHA-256 values for all 14 files, and the three cold Chromium model loads. The
release artifact manifest includes its hash.
